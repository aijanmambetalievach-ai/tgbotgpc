# Тендер Академия — Telegram-бот обучения и консультаций по госзакупкам

Публичный Telegram-бот учебного центра. Через него вы обучаете работе с
государственными закупками Кыргызской Республики и консультируете **закупщиков
(госорганы)**, **поставщиков** и **новичков**.

Клиент открывает бот, выбирает, кто он, и дальше:

- записывается на **живые курсы** (офлайн или Zoom);
- проходит **уроки прямо в Telegram**: видео, тексты и тесты;
- оставляет заявку на **индивидуальное обучение**;
- задаёт вопрос специалисту в разделе **«Консультация»**: можно приложить
  скриншот или документ, ответ придёт в тот же чат.

Отвечает на консультации всегда **человек**: вы или ваши консультанты.
Оплаты в боте пока нет. Клиент оставляет заявку, оплату вы обсуждаете отдельно.

## Возможности

### Для клиента

Меню внизу экрана:

| Кнопка | Что делает |
|---|---|
| 📚 **Обучение** | 🗓 Живые курсы · 📖 Уроки в боте · 🎯 Индивидуальное обучение |
| 💬 **Консультация** | Тема → описание вопроса (можно с файлом) → способ связи → заявка |
| 📋 **Мои заявки** | Статус, переписка со специалистом, «Написать», «Отменить» |
| ❓ **Частые вопросы** | Готовые ответы, кнопка «Не нашли ответ? Спросите специалиста» |
| ℹ️ **О нас и контакты** | Тексты, которые вы редактируете в настройках |
| 👤 **Мои данные** | Имя, телефон, организация, категория |

- При первом запуске бот спрашивает **«Кто вы?»** (закупщик / поставщик / новичок)
  и затем показывает подходящие курсы и уроки. Кнопка «🔎 Показать все»
  открывает весь каталог.
- **Имя и телефон** спрашиваются один раз, при первой заявке. Номер можно
  отправить одной кнопкой. Местные форматы (`0555 123 456`) приводятся к `+996…`.
- **Уроки:** сначала файл (видео, фото или документ), потом текст и кнопки
  «‹ Назад / Далее ›». Если к уроку есть тест, вопросы идут по одному, после
  каждого ответа бот показывает правильный вариант. Пройденные уроки отмечены ✅,
  при повторном прохождении теста сохраняется лучший результат.
- **Уведомления:** клиенту приходят ответ специалиста, «взята в работу»,
  «завершена» и «отклонена» с причиной.

### Для администратора

| Кнопка | Что делает |
|---|---|
| 📥 **Заявки** | Вкладки 🆕 Новые / 🟡 В работе / 📁 Закрытые / Все, карточка с перепиской, выгрузка в Excel |
| 📊 **Статистика** | Клиенты по категориям, заявки по статусам, заявки за 7 дней, пройденные уроки |
| 🗓 **Курсы** | Мастер из 7 шагов, черновик → публикация → архив, ссылка для рекламы |
| 📖 **Уроки** | Текст и (или) видео / фото / документ, аудитория, порядок, тест, предпросмотр |
| ❓ **FAQ** | Добавить, изменить, скрыть или удалить вопрос |
| 👥 **Клиенты** | Фильтр по категориям, карточка, заявки клиента, блокировка, выгрузка в Excel |
| 📣 **Рассылка** | Всем или одной категории: текст, фото, видео, документ |
| ⚙️ **Настройки** | Тексты «О нас» и «Контакты», «👁 Меню клиента» |

- **Новая заявка** сразу приходит всем администраторам вместе с файлом клиента
  и кнопками «✍️ Ответить» и «📂 Открыть».
- **Ответ клиенту:** нажмите «✍️ Ответить» и напишите сообщение. Можно приложить
  файл. Жирный шрифт, курсив и ссылки сохраняются. Первый ответ автоматически
  переводит заявку в «В работе» и закрепляет её за вами. Ответные сообщения
  клиента приходят именно вам.
- **Ссылка для рекламы курса** вида `https://t.me/<бот>?start=course_5` есть в
  карточке опубликованного курса. Она сразу открывает курс у клиента. Ссылка
  `?start=consult` открывает выбор темы консультации.
- **/client** показывает бот глазами клиента, **/admin** возвращает админ-меню.

## Быстрый старт

1. **Создайте бота.** В Telegram откройте [@BotFather](https://t.me/BotFather) →
   `/newbot`, задайте имя и username (должен заканчиваться на `bot`) и
   скопируйте токен.
2. **Узнайте свой Telegram ID**, например через [@userinfobot](https://t.me/userinfobot).
3. **Настройте `.env`:**

   ```bash
   cp .env.example .env
   ```

   ```env
   BOT_TOKEN=123456789:ваш-токен
   BOOTSTRAP_ADMIN_TELEGRAM_IDS=111111111,222222222   # вы и ваши консультанты
   BRAND_NAME=Тендер Академия                         # название в приветствии
   ```

4. **Запустите** через Docker (`docker compose up -d`) или
   [без Docker](#локальный-запуск-без-docker).
5. Напишите боту `/start`. Вы увидите админ-меню.
6. Наполните бот: **⚙️ Настройки** (о вас и контакты) → **❓ FAQ** →
   **🗓 Курсы** → **📖 Уроки**. Новые курсы и уроки создаются как черновики,
   клиенты их не видят, пока вы не нажмёте «🟢 Опубликовать».

Полезно задать в BotFather команды (`/setcommands`):

```
start - Главное меню
help - Что умеет бот
cancel - Отменить текущее действие
```

## Как пользоваться админ-панелью

**Добавить урок с тестом**

1. 📖 Уроки → ➕ Новый урок → название.
2. Пришлите материал: текст **или** видео / фото / документ. Подпись к файлу
   станет текстом урока. Если подписи нет, бот предложит добавить текст отдельно.
3. Выберите аудиторию. Урок сохранится как черновик.
4. 📝 Тест → ➕ Добавить вопрос. Каждый вопрос — одним сообщением:

   ```
   Сколько членов должно быть в закупочной комиссии?
   - Четное число
   + Нечетное число, не менее трех
   - Любое
   ```

   Знаком `+` отмечен правильный вариант, знаком `-` — неправильные.
   Вариантов от 2 до 6. Отправляйте вопросы один за другим, в конце нажмите «Готово».
5. 👁 Предпросмотр → 🟢 Опубликовать.

Порядок уроков задаёт «🔢 Порядок»: уроки показываются по возрастанию номера.

**Рассылка.** 📣 Рассылка → выберите получателей → отправьте сообщение. Бот
покажет, как его увидят клиенты, и сколько человек его получат. Затем нажмите
«✅ Отправить». Рассылка идёт в фоне с паузами, чтобы Telegram не ограничил бота.
В конце придёт отчёт «доставлено N из M».

**Добавить ещё администратора.** Впишите его Telegram ID в
`BOOTSTRAP_ADMIN_TELEGRAM_IDS` и перезапустите бота.

## Переменные окружения

Полный список с комментариями — в [`.env.example`](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|

| `BRAND_NAME` | `Тендер Академия` | Название в приветствии и именах файлов |

| `API_ENABLED` / `API_HOST` / `API_PORT` | `true` / `0.0.0.0` / `8000` | HTTP-сервер health-проверок |
| `LOG_LEVEL` / `LOG_FORMAT` | `INFO` / `console` | `json` — для продакшена |
| `MAX_TITLE_LENGTH` | `300` | Длина названий курсов, уроков, вопросов FAQ |
| `MAX_TEXT_LENGTH` | `3500` | Длина текста урока, описания, ответа, сообщения |
| `MAX_OPEN_APPLICATIONS` | `10` | Сколько открытых заявок может быть у одного клиента |
| `MAX_MESSAGE_LENGTH` | `4000` | Порог обрезки сообщений Telegram |
| `PAGE_SIZE` | `8` | Размер страницы списков |
| `RATE_LIMIT_MESSAGES` / `RATE_LIMIT_WINDOW_SECONDS` | `20` / `10` | Анти-спам |

## Локальный запуск без Docker

Нужны Python 3.12+ и PostgreSQL.

```bash
python -m venv .venv
source .venv/bin/activate           # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt # только рантайм: requirements.txt
cp .env.example .env                # заполнить BOT_TOKEN и BOOTSTRAP_ADMIN_TELEGRAM_IDS
```

Создайте базу (однократно):

```bash
psql -U postgres -c "CREATE ROLE tender LOGIN PASSWORD 'tender';"
psql -U postgres -c "CREATE DATABASE tender OWNER tender;"
psql -U postgres -c "CREATE DATABASE tender_test OWNER tender;"   # для тестов
```

Примените миграции и запустите:

```bash
alembic upgrade head
python -m app.main
```

Вместе с ботом поднимается HTTP-сервер проверок:
<http://localhost:8000/health>, <http://localhost:8000/ready>.

## Запуск в Docker

```bash
cp .env.example .env    # заполнить BOT_TOKEN и BOOTSTRAP_ADMIN_TELEGRAM_IDS
docker compose up -d
docker compose logs -f app
```

Поднимаются `postgres` (с healthcheck и томом для данных) и `app`. Сервис `app`
ждёт готовности БД, сам применяет миграции и проверяет себя через `/health`.
Отключить автоматические миграции: `RUN_MIGRATIONS=false`.

## Миграции

```bash
alembic upgrade head                              # применить
alembic downgrade -1                              # откатить последнюю
alembic revision --autogenerate -m "описание"     # новая миграция по моделям
alembic check                                     # модели и миграции совпадают?
```

> **Переход с прежней версии (бот закупок).** Схема `0001_consulting` новая и
> не продолжает старую историю миграций. Разворачивайте бот на **новой пустой
> базе данных**. Старую базу сохраните дампом, если её данные нужны.

## Тесты, линт, типы

```bash
pytest                       # юнит-тесты (без БД); интеграционные пропускаются
TEST_DATABASE_URL=postgresql+asyncpg://tender:tender@localhost:5432/tender_test pytest
ruff check . && ruff format --check .
mypy app
```

Интеграционные тесты применяют настоящие миграции и проверяют сервисы на
PostgreSQL. Файл `tests/integration/test_telegram_scenario.py` прогоняет
**живые сценарии через диспетчер aiogram**: Bot API в нём подменён записывающей
заглушкой. Например: клиент пишет `/start`, выбирает категорию, задаёт вопрос со
скриншотом и оставляет телефон. Администратор получает уведомление, отвечает и
завершает заявку. Тест проверяет, что каждое сообщение ушло нужному человеку.

## Архитектура и структура проекта

Модульный монолит, один процесс: long-polling бот и FastAPI для health-проверок.
Слои строго разделены: обработчики Telegram тонкие, бизнес-правила и проверка
прав живут в сервисах, SQL — только в репозиториях.

```
app/
├── main.py                  точка входа: бот + HTTP, bootstrap администраторов
├── config/                  настройки (pydantic-settings), логирование
├── database/                движок, сессии, базовые классы моделей
├── models/                  User, Course, Lesson, LessonQuestion, LessonProgress,
│                            Application, ApplicationMessage, FaqEntry, BotText, AuditLog
├── domain/                  чистые правила: права, статусы заявок, формат тестов,
│                            телефоны, безопасность текста
├── repositories/            запросы к БД
├── services/                auth, client, catalog, application, notification,
│                            excel_export, statistics
├── bot/
│   ├── texts.py             все тексты интерфейса
│   ├── callbacks.py         типизированные callback_data
│   ├── keyboards/           client.py, admin.py, common.py
│   ├── states/              FSM-диалоги
│   ├── middlewares/         логирование, анти-спам, сессия БД, регистрация/доступ
│   └── handlers/            common, client, client_flow, admin_applications,
│                            admin_content, admin_misc, errors
└── api/                     /health, /ready
alembic/versions/0001_initial_schema.py
tests/unit, tests/integration
```

**Заявка** (`Application`) бывает трёх типов: запись на курс, индивидуальное
обучение, консультация. Номер вида `ZV-2026-000123` выдаётся атомарным счётчиком
в БД. Статусы:

```
NEW ──► IN_PROGRESS ──► DONE
 │           └────────► REJECTED (с причиной)
 ├──► DONE / REJECTED
 └──► CANCELLED (клиент, пока заявка открыта)
```

Закрытые заявки не переоткрываются: если вопрос остался, клиент создаёт новую.

## Безопасность

- Бот публичный: новый Telegram-аккаунт регистрируется как **клиент**.
  Администраторами становятся только ID из `BOOTSTRAP_ADMIN_TELEGRAM_IDS`.
- Идентификация — по числовому `telegram_id`. Username хранится только для
  отображения и никогда не используется для проверки прав.
- Права проверяются в сервисном слое при каждом действии, а не скрытием кнопок.
  Клиент видит и меняет только свои заявки. Поддельная `callback_data` не даёт
  доступа к админ-функциям: это покрыто тестами.
- Текст клиентов хранится как простой текст и экранируется при выводе. HTML
  (форматирование) принимается только от администраторов. Слишком длинный HTML
  не режется посередине тега, а превращается в простой текст.
- Защита от Excel formula injection: значения, начинающиеся с `=`, `+`, `-`, `@`,
  экранируются апострофом.
- Заблокированный клиент получает отказ ещё до обработчиков и исключается из рассылок.
- Длина ввода, число открытых заявок и частота сообщений ограничены.
- Секреты хранятся только в переменных окружения. `.env` в `.gitignore`, токен
  лежит в `SecretStr` и не попадает в логи. Важные действия пишутся в `audit_logs`.
- Файлы клиентов и уроков не скачиваются на сервер: бот хранит только
  Telegram `file_id`.

## Резервное копирование

- Копия: `pg_dump -Fc -U tender tender > tender_$(date +%F).dump`, восстановление:
  `pg_restore -d tender tender_YYYY-MM-DD.dump`.
- В Docker: `docker compose exec -T postgres pg_dump -U tender -Fc tender > backup.dump`.
- Файлы (видео уроков, скриншоты клиентов) хранятся на серверах Telegram, в
  базе только ссылки на них. Если удалить бота в BotFather и создать нового,
  ссылки перестанут работать: материалы уроков придётся загрузить заново.

## Известные ограничения

1. **Оплаты в боте нет.** Заявка фиксирует интерес, оплата обсуждается вне бота.
2. **Состояние диалогов хранится в памяти.** Перезапуск сбрасывает
   незаконченные диалоги. Сохранённые заявки, уроки и курсы не теряются. Для
   нескольких копий бота нужен `RedisStorage`: он подключается в одном месте,
   в `create_dispatcher`.
3. **Напоминаний о занятиях нет.** Планировщика пока нет. Уведомить группу
   можно рассылкой.
4. **Администраторы задаются через `.env`.** Добавление консультантов из
   интерфейса бота не реализовано.
5. **Уведомления «по возможности».** Если клиент остановил бота, ответ всё равно
   сохраняется в заявке, а неудача доставки пишется в лог. Администратор видит
   предупреждение.
